## Execution, events and ownership

`ConditionalController` resolves the five-operation input frame from public observations and gated raw `PlayerInputReader` input. Existing movement, shooting and Dodge executors accept actions and spend resources. Fire shoots using final Aim; all Enemy in Firing Line conditions instead inspect the same current physical muzzle ray captured before this frame's rule resolution. D03 sees resolved Move (raw Move when no movement Rule wins). Aim does not fire and Fire does not change aim. Conflicting automatic Jump/Dodge requests are resolved by DisplayOrder before reaching the executor; the retained manual tie-break still gives a successful Dodge priority over a same-frame Jump. Dodge retains its original committed direction. Overridden manual press edges are not queued.

Both conditions must match. If both constrain an enemy, intersect their candidate sets so the **same enemy/source** satisfies both facts, subject to each condition's visibility requirements. Do not combine two Bosses' unrelated facts. Explicit damage/hit/threat sources remain associated with their event; a visible public projectile can identify its source without revealing a concealed body. Enemies on Both Sides remains global. Q01 Nearest and Q02 Lowest-Health retain their own explicit visible-target strategies rather than becoming source-target Aim. Player rules consider on-screen publicly visible bodies without terrain LOS rejection from platforms; Camo and genuinely unobservable bodies remain excluded. Event source binding retains its own legality and does not reveal concealed bodies. This player-only observation change does not alter Boss LOS/perception. Boss policy receives no rules, private input or hidden player intentions.

Each real event has an identity, occurrence time and necessary source. Rows consume independently only when their action is accepted. One public `ConditionalDefaults.RuleEventResponseDuration = 0.5` defines both **event lifetime from the actual event** and **ordinary event-response duration from actual action acceptance**, including Took Damage. Primary event and additional state must overlap for acceptance. An additional state becoming true during the event lifetime may enable the action, but cannot revive a consumed/expired event. Running ordinary responses still require their additional state, and new events never refresh their acceptance deadline. Hold Position/Fire count as accepted zero output. All timers use the same scaled combat clock, so pause freezes both. New events enter normal frame resolution, never recursive callback evaluation.

Finite actions accept once per uninterrupted effective state occurrence. Cooldown recovery, ordinary rematching or failed execution does not invent a new occurrence. State-triggered ordinary continuous actions last while their complete condition is true; event-triggered ordinary actions last 0.5 seconds from acceptance while their additional state remains true. Repeat Jumps retains legal grounded repetition within that response. Short Burst, platform transfer and accepted Jump/Dodge finish their actual action rather than the 0.5-second response window. Short Move uses distance and its continuing-state rules below. Real Shot Fired → Fire 1 Shot and Landed → Jump Once loops remain legal and bounded by actual cadence/resources/physics.

Firing starts only from an actual paid shot. An F01 single remains active at most through that shot's primary recovery. An accepted burst stays active between its internal rounds and ends on completion. Held manual LMB and F03 stay active between normal primary shots only while execution continues. Reload, stop and cleanup end it; dry requests and matches never start it. Manual, single-shot, burst and continuous fire can all generate public events; manual actions keep neutral visual feedback. Do not duplicate existing ShotFired notifications used by Boss observation. Initializing actors, preparation, retry or reading a snapshot must not invent action events. Dispose/fight end clears subscriptions and stale references.

Movement actions remain horizontal. Approach Enemy stops within a small horizontal alignment tolerance and resumes only after the target clearly leaves it, including targets above/below. Retreat retains eligible targets and physical collision. Keep Mid Range releases Move within its existing band; Move Toward Center releases on arrival. **Move (Forward / Back)**, M04, travels the existing 1.5-unit short distance relative to actual visible facing at acceptance, freezes that direction, and needs no enemy. A state primary and its optional state must remain true; an event primary launches once and only its optional state must remain true thereafter. Event expiry alone cannot stop it. Success emits Move Finished once; condition failure, collision, timeout or other failure never completes it. A continuously true state cannot restart the short move. **Keep Moving (Left / Right)**, M11, remains ordinary continuous movement with its own independent direction parameter.

**Hold Position** owns Move with zero ordinary horizontal output, suppressing lower/manual movement without freezing gravity or cancelling accepted Dodge/knockback. **Hold Fire** owns Fire with false output, suppressing lower/manual shooting even with no ammo or during reload. It does not recall bullets or cancel an existing reload. Ownership and feedback must represent these valid zero-output actions without fake movement or shot events.

Jump Once uses the real ground-only jump executor. Repeat Jumps may request a new jump after a legal landing while its state remains true; there is no double jump. D01 uses a valid public threat/source direction and fails without one. D02 uses a visible enemy. D03 uses resolved Move or the last movement direction when stationary. D04 uses the original manual world aim point's horizontal side, unaffected by automatic Aim.

Manual and automatic Dodge share the executor's registered-Boss pass-through rules in both preflight and physical execution; terrain still blocks them and ordinary Move cannot pass through Bosses.
