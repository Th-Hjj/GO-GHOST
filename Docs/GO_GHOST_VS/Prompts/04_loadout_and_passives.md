# Prompt 04 — 七槽自由配装、百分比与被动改造

**Astra 思考档位：最高。请在客户端选择；本文件不修改客户端配置。**

先读取并遵守：
- 当前适用的 AGENTS.md、工程协作规则；
- Docs/GO_GHOST_VS/Execution_Contract.md；
- Docs/GO_GHOST_VS/GO_GHOST_Design_Baseline_ZH.md；
- Docs/GO_GHOST_VS/Prototype_Test_Profile.md；
- Docs/GO_GHOST_VS/Implementation_Log.md（若存在）。
需要核对 Macro 时，读取同目录原表或 Macro_Readable_Extract.md；不要从旧 README 推断新玩法已实现。
只执行本阶段，按 Execution_Contract 的格式交付，完成后停止。

目标：让下一位警察真正能自由选配装，并证明身体比例和强化来自本次配置，而非 UI 假变化。

保留七个独立槽位：左手、右手、左腿、右腿、脊椎、大脑、武器。
使用 Prototype_Test_Profile 的 TEST-v0 权重；六个身体槽的最高贡献相加为 100%，武器永远 0%。
先完成 TEST_HandPower（左手 10%，伤害×1.25）和 TEST_LegRecovery（右腿 10%，闪避冷却×0.75）。
脑部 AI 的实际接管留给 05；尚未实现的模块不可显示为可用或可装备。

任务：
1. 首次失败后所有已经实现的选项同时开放，安装/卸下/替换免费，没有币种/点数/死亡次数解锁。
2. 显示七槽、当前选项、当前总比例、单项变化、实际收益、已知控制接管说明和明显的部署按钮。
3. 未实现槽标“本原型暂无选项”，不画成“再死几次会解锁”。可以清空所有身体槽，仍保留一把基础枪并以 0% 部署。
4. 预览属于草稿；部署复制/冻结本次数据。运行时入口拒绝换装，不能只隐藏按钮。与 Unity 共享资产相关的数据不要被战斗过程写回。
5. 每次部署从基础参数重新计算改造效果，不以安装/重试次数累计乘倍数。死亡后再部署恢复该构型对应的完整状态。
6. 武器与身体改造贡献在逻辑上分开。基础枪足够，不为测试不计比例而造完整武器库。
7. 加入最小可见改造标记/外观预览，使玩家看得出自己更换了身体配置；不要求正式美术。

自动检查/手工检查：
- 所有身体槽清空等于 0%，左右槽互不串值。
- 安装左手得 10%，再装右腿得 20%，卸回后恢复正确数字与实际属性。
- 连续安装/卸下/重试，伤害和闪避冷却无漂移或叠加。
- 不同武器数据的测试夹具贡献都为 0%；测试夹具不可冒充玩家可用武器。
- 修改草稿或尝试局内调用装备接口，不会改变已部署配置。
- 0% 拒绝改造再战仍可用全部基础操作。
- 原型 UI 明示 TEST 权重；不要把当前可装备内容归一化到 100%。

只做到七槽/比例/两项被动强化可用；不要伪造脑模块已完成。
