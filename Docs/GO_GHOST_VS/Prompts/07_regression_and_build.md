# Prompt 07 — 回归测试、修复与独立试玩构建

**Astra 思考档位：最高。请在客户端选择；本文件不修改客户端配置。**

先读取并遵守：
- 当前适用的 AGENTS.md、工程协作规则；
- Docs/GO_GHOST_VS/Execution_Contract.md；
- Docs/GO_GHOST_VS/GO_GHOST_Design_Baseline_ZH.md；
- Docs/GO_GHOST_VS/Prototype_Test_Profile.md；
- Docs/GO_GHOST_VS/Implementation_Log.md（若存在）。
需要核对 Macro 时，读取同目录原表或 Macro_Readable_Extract.md；不要从旧 README 推断新玩法已实现。
只执行本阶段，按 Execution_Contract 的格式交付，完成后停止。

目标：准备能交给别人试玩的可执行版本。本阶段不增加新功能；补回归、修复阻塞、接好构建。

先读 Playtest_Checklist.md，检查设计约束和真实场景引用。
尽量使用现有测试设施；无测试能力则报告，不为了绿色报告引入大依赖或仅检查字符串。

至少验证：
1. New Game 的第一次始终 0% + 基础武器，直接获胜能正常结束。
2. 首次失败后一次开放所有已实现模块；后续失败无币、无新解锁，始终可拒绝身体改造。
3. 连续至少 10 次失败/部署无残留 HP、弹体、攻击、计时器、输入监听、UI 或乘算强化。
4. 六槽权重最高合计 100%，武器永远 0%，当前可用全装为 60%；左右槽独立。
5. 反复替换与卸除恢复基础属性；草稿、锁定配装、胜利记录互不意外引用可变对象。
6. AI 只管瞄准；鼠标/设置/热键不能关掉；无目标时不回退手动；松开射击不自动开火；卸除后下一次恢复手动。
7. 结局边界 0、40 及两侧、100 正确；相同百分比但不同测试构型/历史/武器，结果 ID 相同。
8. 同时死亡只结算一次；战斗结束的迟到攻击不伤到下一位警察。
9. 返回标题/New Game 后恢复初始状态；正常入口没有调试快速装备/强制胜败。
10. 进入/退出 Play Mode、目标分辨率、窗口失焦/恢复，以及独立构建的输入和 UI 行为正常。

数据逻辑、状态转换、场景运行和真人手感四种证据分别记录。模拟 Boss 死亡不算证明 0% 难度可行。
允许局部修复确认的缺陷；不要用删功能、降低测试覆盖或重写整套项目的方式让测试通过。

构建：
- 根据实际环境，优先生成可运行的 Windows 试玩包，包含该目标需要的所有伴随文件，不只拿一个 exe。
- 不擅自升级 Unity 或安装缺失构建模块。构建失败时留下准确错误、命令、日志和最小下一步，不宣称构建成功。
- 明确正确入口、启动方法、当前操作、build 标识/对应 commit 或工作区状态、TEST 参数版本、已知限制。
- 检查无 Missing Script/丢失引用，构建内没有 Editor 依赖、无意的旧关卡入口或调试作弊按钮。
- 生成或更新简短 Playtest_Readme.md 与 Implementation_Log.md；构建输出遵守现有 .gitignore/LFS 规则，不自动上传或发布。

完成后给出 PASS/FAIL/NOT_RUN/BLOCKED 表，并明确此版本是否已有实际运行证据。
停止，不主动添加第二阶段 Boss、第二把武器或更多模块。
