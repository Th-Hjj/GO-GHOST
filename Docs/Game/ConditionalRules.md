## Execution, events and ownership

`ConditionalController` resolves the five-operation input frame from public observations and gated raw `PlayerInputReader` input. Existing movement, shooting and Dodge executors accept actions and spend resources. Fire shoots using final Aim. Historical A40 observes the current physical muzzle ray but is no longer a valid selectable condition. D03 sees resolved Move (raw Move when no movement Rule wins). Aim does not fire and Fire does not change aim. Legal Jump precedes Dodge for automatic, manual and mixed requests. The real jump executor interrupts an active Dodge before applying jump velocity. Dodge retains its original direction until completion or interruption. Overridden manual press edges are not queued.

All conditions must match. Intersect every enemy-constraining candidate set so the **same enemy/source** satisfies all those facts, subject to each condition's visibility requirements. Do not combine two Bosses' unrelated facts. Explicit damage/hit/threat sources remain associated with their event; a visible public projectile can identify its source without revealing a concealed body. Historical A39 remains a global observation but is no longer selectable. Auto Aim Nearest and Lowest Health retain their own explicit visible-target strategies rather than becoming source-target Aim. Player rules consider on-screen publicly visible bodies without terrain LOS rejection from platforms; Camo and genuinely unobservable bodies remain excluded. Event source binding retains its own legality and does not reveal concealed bodies. This player-only observation change does not alter Boss LOS/perception. Boss policy receives no rules, private input or hidden player intentions.

Each real event has an identity, occurrence time and necessary source. Rows consume independently only when their action is accepted. One public `ConditionalDefaults.RuleEventResponseDuration = 0.5` defines both **event lifetime from the actual event** and **ordinary event-response duration from actual action acceptance**, including Took Damage. Move uses that event lifetime directly, without an extra acceptance window. Every event needs a live occurrence overlapping all other conditions at acceptance. Multiple event conditions consume their matched occurrences together, independently for each rule; repeated copies of the same event condition may use the same occurrence. A state becoming true during those windows may enable the action, but cannot revive a consumed/expired event. Running ordinary responses still require all their state conditions, and new events never refresh their acceptance deadline. All timers use the same scaled combat clock, so pause freezes both. New events enter normal frame resolution, never recursive callback evaluation.

Finite actions accept once per uninterrupted effective state occurrence. Cooldown recovery, ordinary rematching or failed execution does not invent a new occurrence. State-triggered ordinary continuous actions last while their complete condition is true; event-triggered ordinary actions other than Move last 0.5 seconds from acceptance while all their state conditions remain true. Move ends when its event conditions expire. Jump (Repeat) retains legal grounded repetition within that response. Short Burst, platform transfer and accepted Jump/Dodge follow their actual action rather than the 0.5-second response window; legal Jump can interrupt Dodge without refunding its consumed occurrence. Move uses live condition eligibility as described below. Real Shot Fired → Fire 1 Shot and Landed → Jump (Once) loops remain legal and bounded by actual cadence/resources/physics.

The internal weapon firing process (no longer a selectable condition) starts only from an actual paid shot. An F01 single remains active at most through that shot's primary recovery. An accepted burst stays active between its internal rounds and ends on completion. Held manual LMB and F03 stay active between normal primary shots only while execution continues. Reload, stop and cleanup end it; dry requests and matches never start it. Manual, single-shot, burst and continuous fire can all generate public events; manual actions keep neutral visual feedback. Do not duplicate existing ShotFired notifications used by Boss observation. Initializing actors, preparation, retry or reading a snapshot must not invent action events. Dispose/fight end clears subscriptions and stale references.

Movement actions remain horizontal. **Move**, M11, uses Left / Right / Toward Enemy / Away from Enemy / Arena Center. Left/Right are fixed world directions; enemy options retain the existing visible target selection. Toward Enemy holds zero inside the existing horizontal alignment tolerance and resumes when the target leaves it. Arena Center releases on arrival. All five branches execute only while every condition remains true, including the actual live window of event conditions. Condition loss immediately releases automatic Move to lower rows/manual input. No fixed distance, completion event, finite-occurrence consumption or completion wait remains. Physical collision and unavailable-target fallback are unchanged.
